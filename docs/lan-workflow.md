# 局域网多人联调工作流

> 适用场景：2–5 人小组，Android 调试机走内网 `http://<IP>:8899` 直连一台常驻的 EasyCharles。
> 单机自用不需要本文，看 `README.md` 就够。
>
> 相关：`scripts/deploy/DEPLOY.md`（发布包部署细节）、`docs/decisions.md` ADR-015（数据面为何不鉴权）、
> ADR-017（快照能力 URL）、ADR-014（HTTPS 反代的限制）、ADR-022（发布包形态）。

---

## 0. 一句话结论

**一台常驻「联调服务器」+ 每人自己的手机号空间 + 快照当协作货币。**
三件必做：① 服务器地址固定；② 改口令并把它关在可信网段里；③ 有价值的记录立刻做快照。

---

## 1. 三种拓扑与取舍

```
   Mac A / 同事的机器                     安卓调试机
   只开浏览器看控制台                       baseUrl = http://10.0.0.1:8899
        └──────────────┬──────────────────────────┘
                       ▼
        ┌──────────────────────────────────────┐
        │  常驻联调服务器（一台 Mac 或 Linux）    │
        │  systemd / launchd 自启 · 固定内网 IP   │
        │  数据面 / 控制面 / 管理面 / 快照面      │
        └──────────────────────────────────────┘
```

| 方案 | 适合 | 优点 | 代价 |
|---|---|---|---|
| **A 单机** | 1 人、涉密接口 | `adb reverse` + 服务只监听回环，**最安全**（ADR-015 的原始设计） | 只有插着手机的那台机器能看记录，同事看不到 |
| **B 常驻服务器（推荐）** | 2–5 人小组 | 一份记录全员可见；服务不随谁的机器休眠 | 数据面不鉴权 → **网络边界就是唯一防线**；mock 规则全局共享会撞车（见 §4） |
| **C 每人一台** | 各自改 mock、互不干扰 | 完全隔离 | 没有共享视图 |

**常规组合：B 为主，C 兜底。**
需要互不相同的 mock 时，在本地再起一个实例，把共享实例当"抓包 + 快照看板"。

> **跨方案的通用货币是快照**：快照面是免登录的能力 URL（token 即凭据、只有 GET、TTL 可设，
> ADR-017），谁都能打开，不要求两台机器网络互通。方案 C 的人也能把快照丢进群里一起排查。

> ⚠️ `adb reverse tcp:8899 tcp:8899` 只对**手机插着的那台机器**生效，所以它属于方案 A，
> **不能**用来连远端的常驻服务器。想让手机连共享实例，只能走 WiFi + `--lan`。

## 2. 常驻服务器落地清单

### 2.1 地址必须固定（硬要求，不是建议）

SDK 的地址是**代码里配的**：

```kotlin
EasyCharles.init(this, EasyCharles.Config(baseUrl = "http://10.0.0.1:8899"))
```

SDK 内部 SharedPreferences 只存 deviceId，**没有运行时改地址的能力**（除非宿主 App 自己做了
Test 页让运行时填）。所以服务器 IP 一变，**所有调试包都要重新打包**。

做法（任选）：路由器 DHCP 保留（推荐）→ 手写静态 IP → 路由器 DNS 别名。
**别指望 `<主机名>.local`**：Android 侧 mDNS 解析不可靠。

### 2.2 启动方式

| 目标机 | 做法 |
|---|---|
| Linux | 包内 `easy-charles.service`（systemd，非 root 用户 + `EnvironmentFile=` 装口令） |
| macOS | 双击包内「安装后台服务.command」（launchd 用户级 agent，开机自启 + 崩溃拉起） |

细节与排错见 `DEPLOY.md`；macOS 侧注意 launchd 的 `PATH` 很窄，安装脚本会把 node 写成绝对路径。

### 2.3 口令与管理员

```
EC_PASSWORD=<真实口令>        # 默认 123456 只适合本机自用
EC_ADMIN=13800000000          # 管理员手机号白名单，逗号分隔；不配 = 没有管理员（ADR-018）
```

- 口令是**全局单一口令**（不是每用户密码）；用户之间靠**手机号空间 + 设备绑定**隔离（ADR-015）
- 管理员比普通用户多"能看到全部设备"，方便帮别人排查 → **只给一个人**（比如组长）

### 2.4 网络边界（ADR-015 的直接后果）

数据面 `/__ec/p*` 按设计**不鉴权**（为了 `adb reverse` 场景零暴露），所以 `--lan` 等于让这台机器
变成一台**开放中转代理**：同网段任何人都能借它的 IP 发请求。能做的：

- ✅ 放在**独立的联调 Wi-Fi / VLAN**，不要和生产网同段
- ✅ 只在联调期开着；平时双击「卸载后台服务.command」停掉
- ❌ 绝不做公网端口映射
- ⚠️ macOS 自带那个"防火墙"只能**按应用**放行，**不能按网段**；要按来源 IP 限制得写 pf 规则
- ⚠️ 不要给共享实例套 HTTPS 反代：当前代码 `wsUrl` 恒 `ws://`（ADR-014），控制台会撞 mixed content

### 2.5 容量参数（多人共享必须调）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--record-mode` | `full` | `full` 原样存 body；`sample` 只留前 `--sample` 字节；`meta` 只留大小不留 body |
| `--sample` | 8192 | `sample` 模式的截断字节数 |
| `--max-records` | 2000 | 记录条数上限 |
| `--snapshot-ttl` | 168 | 快照有效期（小时），`0` = 永不过期 |

**记录本身只在内存，重启即丢**（规则 / 用户绑定 / 快照是落盘的）。
共享实例的常规配置：

```
EC_ARGS="--record-mode sample --sample 65536 --max-records 5000"
```

### 2.6 兼容层参数（第三方 mock SDK 必配）

`--compat-*` / `--app-id` 没有对应的 `EC_*` 变量，用 `EC_ARGS` 透传：

```
EC_ARGS="--compat-route /mock-proxy --compat-target-header <原始URL头> --compat-device-header <设备名头> --app-id <你们 App 的 appId>"
```

- 头名以你们 App 侧 mock SDK 为准，`easy-charles.conf.example` 里有形状示例
- **漏配的典型症状**：手机连上了、首页却是 404/接口全断 —— 因为改写后的请求没被兼容层接住
- 优先级：`命令行 > EC_* > EC_ARGS > 默认值`，所以 `EC_ARGS` 抢不过任何显式设置

### 2.7 数据与备份

数据目录（Linux `/var/lib/easycharles`、macOS `~/Library/Application Support/EasyCharles/data`）里的
`rules.json` / `store.json` / `snapshots/` 是**团队资产**，和代码一起备份。

### 2.8 健康检查

用 `GET /`（返回 200 且含 "EasyCharles"）。**不要**用 `/__ec/api/health`：`/__ec/api/*`
除 login 外都要会话，未登录一律 401。

## 3. 日常协作流

1. 每人用**自己的手机号**登录控制台（手机号 = 空间；**同号 = 同空间**，会互相看到记录、也都能改规则 → 别共用）
2. 调试包 `baseUrl` 指向常驻服务器 → 首次登录会看到"未绑定设备" → 绑定到自己的空间
3. 正常跑业务，控制台只看自己设备的记录（顺序 mock 的指针按 `deviceId` 隔离，互不踩）
4. 需要复现的接口配 mock；要 A/B 对比用顺序 mock
5. **看到有价值的记录立刻做快照** —— 记录重启就丢，快照落盘 + 免登录链接，直接发群里/贴工单
6. 联调结束：确认共享实例里没留敏感数据；不长期用就停掉服务

**发布新版（开发机 → 那台常驻服务器）**：改完代码在开发机跑一条命令即可，
门禁/打包/传输/校验/换版本目录/重装/健康检查/回滚命令一条龙：

```bash
scripts/deploy-to-lan.sh mac-b          # 首次加 --init（提示设口令）
```

角色是刻意分开的：**开发 + 构建都在开发机**（工具链齐全，门禁跑在这里），
**服务器只跑服务**（只要 Node）。手机和 App **不需要任何改动**（地址端口没变），
发版会清空抓包记录（只在内存），规则/绑定/快照不受影响。细节与坑见包内 `DEPLOY.md` §3C。

## 4. mock 规则是全局的（共享方案唯一的真痛点）

`rules.json` 是**实例级一份**，没有按人隔离 —— 只有顺序 mock 的指针按 `deviceId` 隔离。
也就是说：**你加的规则会影响别人的请求。**
（这是 ADR-018「边界 4」明确维持的现状，延续 ADR-016 的「规则全局生效」；改成按空间隔离与
ADR-016 直接冲突，收益不值那个价。所以工作流要绕开它，而不是指望它改。）

- ✅ 规则写具体（host + path + params），别用宽泛匹配抢别人的流量
- ✅ 约定"谁开谁负责"：用完关掉或删掉（规则可单条启停/删除）
- ✅ 需要私有 mock → 本地起实例（方案 C），共享实例只做抓包与快照
- ❌ 最差实践：所有人往共享实例塞宽泛 mock，然后互相困惑"我的请求怎么被改了"

## 5. 反模式

- 把 `8899` 映射到公网，或放在生产网长期开着
- 给共享实例套 HTTPS 反代（ADR-014 未支持）
- 所有人共用一个手机号登录（空间与规则都会混）
- 指望"历史回看"：记录重启即丢，长跑靠调大 `--max-records` + 及时快照
- 依赖会变的服务器 IP（见 §2.1）

---

## 6. 已知限制

- 📅 数据面不鉴权（ADR-015，刻意取舍）——**网络边界就是防线**
- 📅 记录只在内存，重启即丢；历史回看未实现
- 📅 mock 规则无按人隔离：`rules.json` 全局单文件、对所有登录用户可写（ADR-018 边界 4）。
  **已定契约待实现**：ADR-033 / 协议 C14 把它改成「私有项目参与命中 + 共享项目只读模板」，
  见 roadmap P7，落地前本条限制仍然成立
- 📅 HTTPS 反代不支持：`wsUrl` 恒 `ws://`（ADR-014）
- 📅 服务端无优雅停机（未处理 `SIGTERM`），停止即终止；`rules.json` / `store.json` 写时落盘不受影响
