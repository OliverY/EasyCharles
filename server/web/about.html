不装证书的客户端接口联调工具：
把「网络层劫持」换成「应用层显式引流」

Charles 类工具靠中间人证书在 CONNECT 隧道里解密流量；EasyCharles 放弃这条路—— App 内的拦截器把请求显式改写发往本地服务，本地服务再转发到真实服务器， 在这个中转过程中完成记录、mock、顺序返回与解密展示。因此没有根证书、不碰 TLS、 也不受证书绑定（pinning）影响。

不装根证书 不受 pinning 影响 顺序 mock + 设备隔离 控制面 / 数据面分离 fail-open 不阻塞业务 代价：需要接入 SDK（仅 debug）

01架构原理图

三条链路：数据面（App → 本地服务 → 真实上游）、控制面（SDK / 控制台 ↔ 本地服务 WebSocket）、 管理面（浏览器 ↔ 控制台 API）。控制面与数据面严格分离，任一断线不影响转发。

SDK 拦截器（承接数据面 + 控制面） 本地服务内部模块 能力边界与取舍 灰色箭头 = 数据面&接入通道　绿色箭头 = WebSocket 控制面

一个请求的完整生命周期

  1. SDK 缓冲 request body（body 只能写一次，后续所有回放基于快照）
  2. SDK URL 改写为 /__ec/p<path>，注入 X-EC-Target / Device-Id / Session-Id / App-Id / Seq
  3. 服务 解析 X-EC-Target 得到真实目标；失败返回 400 EC_BAD_TARGET
  4. 服务 规则引擎命中？→ mock（序列指针 / delay），否则 passthrough
  1. 服务 剥离全部 X-EC-* 与 hop-by-hop 头，重写 Host，强制 Accept-Encoding: identity
  2. 服务 转发上游：默认 ≤512KB 缓冲转发，否则流式；上游错误 → 502/504，绝不重试
  3. 服务 响应边转发边缓冲，记录实际传输字节数；超阈值只留采样
  4. 服务 组装 Record → Store → 按设备归属推送控制台
为什么拦截器必须放最外层：addInterceptor 先加的更外层。捕获拦截器在最外层时， 请求方向抓到的是加密前的明文，响应方向抓到的是解密后的明文；放反了就只能看到密文。

02客户端如何接入

接入 = 让 App 的请求先到本地服务。先选连接通道（决定 baseUrl），再按平台挂拦截器。 服务端只认协议不认端类型，所以接入成本 ≈ 实现协议。

2.1 选一条连接通道

方式做法baseUrl说明
真机 USB（推荐） adb reverse tcp:__EC_PORT__ tcp:__EC_PORT__ http://127.0.0.1:__EC_PORT__ 不用连 WiFi；服务可只监听回环地址，最安全
Android 模拟器 无需额外配置 http://10.0.2.2:__EC_PORT__ 10.0.2.2 是模拟器里的宿主机回环
iOS 模拟器 无需额外配置 http://localhost:__EC_PORT__ 模拟器与宿主机共享网络
真机 WiFi 服务端加 --lan http://<电脑内网IP>:__EC_PORT__ 见下方安全提示，用完即关
局域网模式的代价：数据面不鉴权，--lan 会让你的机器等价于一个开放中转代理， 同网段任何人都能借你的 IP 发请求。只在可信网络里临时开启。

2.2 Android 接入（5 步）

  1. 引入 SDK 模块
    settings.gradle.kts
    include(":easy-charles")
project(":easy-charles").projectDir = file("../easy-charles/android-sdk/easy-charles")
    app/build.gradle.kts —— 只在 debug 构建引入，release 包里一行代码都不会有
    dependencies {
    debugImplementation(project(":easy-charles"))
    implementation("com.squareup.okhttp3:okhttp:4.12.0")
}
    SDK 对 OkHttp 是 compileOnly，实际版本由宿主 App 提供，避免版本冲突。
  2. 允许明文（仅 debug sourceSet）
    Android 9+ 默认禁明文。放到 app/src/debug/res/xml/network_security_config.xml：
    <?xml version="1.0" encoding="utf-8"?>
<network-security-config>
    <domain-config cleartextTrafficPermitted="true">
        <domain includeSubdomains="false">127.0.0.1</domain>
    </domain-config>
</network-security-config>
    app/src/debug/AndroidManifest.xml
    <manifest>
    <application android:networkSecurityConfig="@xml/network_security_config" />
</manifest>
  3. 初始化（Application.onCreate）
    class App : Application() {
    override fun onCreate() {
        super.onCreate()
        EasyCharles.init(
            this,
            EasyCharles.Config(
                // 模拟器 10.0.2.2；真机 USB 用 127.0.0.1
                baseUrl = "http://127.0.0.1:__EC_PORT__",
                reportUserName = false,   // userName 属个人信息，默认不上报
                env = "test",
            ),
        )
    }
}
    非 debuggable 进程里所有能力自动 no-op（debugImplementation + BuildConfig.DEBUG + 运行时 FLAG_DEBUGGABLE 三重保险）。
  4. 挂拦截器（顺序是关键）
    val client = OkHttpClient.Builder()
    .addInterceptor(EasyCharlesInterceptor())  // ← 必须放在最外层
    .addInterceptor(yourCryptoInterceptor)     // ← 业务的加解密拦截器
    .build()
  5. 业务信息打标（可选）
    登录成功后调用，控制台设备标签会实时刷新：
    EasyCharles.setUser(userId = "10086", userName = "张三")
EasyCharles.setEnv("test")
EasyCharles.setTags(listOf("IM", "支付"))
首次联调：启动本地服务 → 打开控制台（返回控制台）→ App 启动后设备列表出现你的机器 → 点「绑定」把它划进你的手机号空间，之后记录只对该空间可见。

2.3 iOS 接入（P5 预留）

服务端只认协议不认端类型，iOS 端接入成本 ≈ 实现协议：把 URLProtocol 子类挂到 URLSessionConfiguration.protocolClasses，在 startLoading 里做与 Android 相同的 URL 改写与 X-EC-* 头注入；ATS 明文用 NSAllowsLocalNetworking 放行本地地址。

协议契约见 docs/protocol.md；当前仓库只提供 Android SDK。

03协议速查

协议 v__EC_PROTOCOL__ 是三端唯一的契约基准。完整定义见 docs/protocol.md。

三个面

面用途路径鉴权
数据面请求转发与记录/__ec/p<原始 path>不鉴权（依赖监听地址边界）
控制面设备注册 · 心跳 · 实时推送 · 下发指令WS /__ec/wsSDK hello 免鉴权；控制台 subscribe 必填登录会话
管理面控制台 API 与静态资源/__ec/api/*、/、/about仅 /__ec/api/login 免鉴权，其余 API 必填 X-EC-Session

数据面请求头（SDK → 服务端）

Header必填说明
X-EC-Target是原始完整 URL（含 scheme / host / path / query），必须可被 new URL() 解析
X-EC-Device-Id是安装级 UUID，跨会话稳定；用于设备去重与记录归属
X-EC-Session-Id是SDK 每次初始化生成
X-EC-App-Id是packageName（Android）/ bundleId（iOS）
X-EC-Seq否单调递增序号，用于排序与去重；重定向链各跳共享同一值
X-EC-Record-Mode否full | meta | sample，覆盖服务端全局配置
X-EC-Redirect否1 表示重定向链非首跳，服务端据此置 flags.redirected
X-EC-Token否预留字段，当前服务端不校验；留给后续可选数据面鉴权（P1）
所有 X-EC-* 头在转发上游前会被全部剥离，不会泄漏给真实服务器。

04安全边界与降级

机制行为
fail-open连不上本地服务时，SDK 用重建的等价请求直连真实服务器，业务层无感知；连续失败 3 次后熔断，冷却后半开探测自动恢复
不重试上游失败上游 502/504/503 属真实业务失败，绝不重试，避免重复提交
release 三重保险debugImplementation + BuildConfig.DEBUG + 运行时 FLAG_DEBUGGABLE 校验，非 debuggable 进程全部 no-op
设备身份deviceId 用自建 UUID 存 SharedPreferences，不用 ANDROID_ID（会变）也不用 IMEI（无权限 + 合规风险）
隐私userName 默认不上报，需要时显式打开 reportUserName
控制台登录手机号 + 全局口令（--password，默认 123456，共享网络下必须改）；首次登录即注册该手机号空间
数据可见性设备绑定到手机号空间后，其他空间看不到它的记录；查询与推送都按归属过滤；绑定关系落 .data/store.json，重启保留
明确的取舍：数据面无鉴权 ⇒ 任何能访问该端口的人都能把它当中转代理用。因此默认只监听回环 （adb reverse / 模拟器零暴露），--lan 只在可信网络短时开启、用完即关。 可选的数据面鉴权（复用预留的 X-EC-Token）在路线图 P1。
